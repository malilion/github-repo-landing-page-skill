Open source · NYC & Toronto

Unify email, chat, docs, tasks, agents, and CRM in one fast interface.

Macro is the all-in-one workspace for you and your team. Everything is @linked and searchable so your team — and your agents — never have to switch tools. Designed in NYC and Toronto, built in SolidJS and Rust, fully open source under AGPL-3.0.

01 — Product

Six surfaces, one bidirectional graph

Live UI captures from a signed-in Macro workspace on 29 October 2026. The CRM board uses fictional sample companies and deal values.

Before

Five excellent products that do not form a system

The Macro team used Slack, Linear, Notion, HubSpot, and Superhuman. As a prior venture scaled toward about 20 people, every team got its own tools and the company was held together by MCP and Zapier. The company was not computable.

After

One operating system, redesigned from the ground up

Macro is a complete redesign of work software as a single system. Each surface is purpose-built, and every one of them shares the same backend. Cross-references between a doc and a task, or a channel message and an email, are stored as a bidirectional graph.

02 — System

How the blocks become one workspace

Each block is designed to be best in class on its own. Where it comes together is how they work together: @links, channel permissions, team memory, and one inbox.

@mention anything; both sides remember

@mention a doc in a message and both know about each other. Your workspace becomes a web of context you can navigate in either direction. The same graph ties customer support emails into support channels, and CRM records into the conversations that update them.

Modular blocks

Click a block to see how it connects. Every surface shares the same backend.

Multi-account unified inbox, keyboard shortcuts, and shared inboxes. Gmail. Draft, edit, and send from AI chats. Built-in window manager for 3+ splits. Native company and contact objects so you can jump from an address to every thread with that person or company.

Messages

Channels and direct messages for focused technical discussions. The first replies show inline; the rest collapse into a thread. Threads are permissioned separately so you can share them across channels. Agents are first-class citizens, like human users.

Tasks

Linear-inspired tasks tightly coupled to channels, email, and agents so tracking happens where the conversation happens. Create from an email, from c t, from /task in a doc, from a - [ ] bullet, via @Macro, in any agent chat, or through MCP, API, or SDK.

Docs

Markdown-native docs with live CRDT collaboration and Cloudflare Durable Objects. History and forking, offline editing, @links to email, tasks, messages, companies, and contacts. Agents edit as peers in the same CRDT system. Mobile-friendly on the web and iOS.

Docs →

Canvas

A 2D board with embedded @links to tasks, files, and emails — for the work that is too spatial for a list and too connected to live in a separate whiteboard.

Agents

Team-level memory synthesized from conversations, DMs, email, tasks, and calls — stored in markdown, portable across OpenAI, Google, Anthropic, and MCP. Tool coverage of nearly everything in the Macro UI, with no rate limits on MCP.

Calls

Recorded, transcribed, and logged to team memory so agents can act on what was said — not only on what was typed in a chatbot.

File storage

04 — Start

Hosted app, MCP, or the open-source tree

Sign up on the hosted app, point a coding agent at the workspace over MCP, or clone the repository. Local stack details live in Running locally and CONTRIBUTING.md.

https://macro.com/app

Sign up at macro.com/app and connect Gmail or Google Workspace. Macro runs in any modern browser. There is an iOS app; an Android app is listed as coming soon. The getting started guide takes a fresh account to a working setup in about 15 minutes.

Point Claude Code, Codex, or any MCP client at your workspace. See MCP setup and agent recipes. The README states there are no rate limits on MCP, with near 100% coverage of the Macro UI.

Clone the public repository. Frontend-only work can run against hosted services; backend, database, or on-machine behavior uses the local stack. Follow Running locally. The frontend uses bun and Vite. A Nix shell is available via nix develop.

The Mintlify site for docs.macro.com lives in apps/docs. Mintlify currently requires an LTS Node release (Node 20 or 22) for CLI commands. Generated MCP tool pages are rebuilt from crates/ai_tools.

The SolidJS client is also bundled with Tauri for desktop. You need Rust, the Tauri CLI, and bun. In a Nix shell the CLI is installed for cargo. cargo tauri dev runs the desktop app for the host OS; cargo tauri android dev and cargo tauri ios dev are documented for those targets. Focused shells: nix develop .#tauri-linux and nix develop .#tauri-android.

Open an issue before a PR. Use Conventional Commits for branches and titles.
