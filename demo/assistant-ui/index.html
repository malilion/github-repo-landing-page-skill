What each layer owns

UI layer

Primitives and prebuilt components render the thread, messages, composer, message parts, actions, attachments, and suggestions. They read and write through the runtime context.

Runtime layer

The boundary between UI and backend. It owns or adapts messages, thread state, composer state, run lifecycle, branching, editing, and regeneration. LocalRuntime keeps state internal. ExternalStoreRuntime delegates to your store.

Backend / agent layer

Produces assistant output: text, message parts, tool calls, metadata, agent state, attachments, or other events that the runtime maps into UI state.

Integration / protocol layer

Adapters bridge AI SDK, LangGraph, LangChain, ADK, A2A, AG-UI, OpenCode, or your own backend. DataStream and AssistantTransport let a generic backend talk to assistant-ui without a custom adapter per app.

Persistence layer

Thread and message history can live in Assistant Cloud or in your own database through thread and history adapters. Persistence stays separate from rendering and from model generation. The runtime coordinates with it.

Capabilities

What the repository actually ships.

Filtered from the README, the primitives docs, and the package manifests in this checkout. Versions below are those manifest versions.

Primitives

Composable primitives

Build a chat from Thread, Message, Composer, ThreadList, ActionBar, and related parts. Style every pixel, or start from the shadcn/ui theme the CLI copies into the project.

Primitives

Radix-style parts

Each primitive uses Root plus named parts, asChild, and AuiIf. They read the nearest AssistantRuntimeProvider, so there is no prop drilling for chat state. The docs list Composer, Thread, Message, ActionBar, BranchPicker, ThreadList, AssistantModal, Attachment, Suggestion, SelectionToolbar, Error, and ChainOfThought.

Production UX

Streaming chat behavior

The README includes streaming, auto-scroll, retries, attachments, markdown, code highlighting, voice dictation, keyboard shortcuts, and accessibility.

Production UX

Strong TypeScript

Typed runtime APIs, tool schemas, message parts, and adapters end to end. @assistant-ui/react 0.15.32 describes itself as an open-source TypeScript/React library for production-grade AI chat.

Generative UI

Tools as React

Render tool calls and JSON as React components, collect inline human approvals, and expose safe frontend actions to the model. @assistant-ui/generative-ui 0.0.8 is the framework-neutral package in this repo.

Runtimes

Swap the runtime

useChatRuntime connects to the Vercel AI SDK. Swap it for useLangGraphRuntime, useDataStreamRuntime, or any custom runtime. @assistant-ui/ai-sdk in this repo is 0.0.16.

Runtimes

Providers named in the README

OpenAI, Anthropic, Google Gemini, Mistral, Perplexity, AWS Bedrock, Azure, Fireworks, and Ollama, plus community providers through the AI SDK, and a custom HTTP backend. The installation guide also documents Groq, Cohere, Google Vertex, and Chrome AI.

Surfaces

Web, Vue, native, terminal

Docs overview: components, runtimes, and primitives for React, Vue, React Native, and the terminal. This checkout has @assistant-ui/vue 0.0.7, @assistant-ui/react-native 0.1.51, @assistant-ui/react-ink 0.0.54, and framework-agnostic @assistant-ui/core 0.3.32. The CLI scaffolds Expo with --native and React Ink with --ink.

Cloud

Assistant Cloud

Optional hosted backend. The cloud docs describe persistence, thread titles, run reports, OpenTelemetry traces, engagement, intelligence, and a dashboard. The assistant-cloud package in this repo is 0.2.9. The README also lists it for managed thread history, telemetry, and file storage.

Install

Commands taken from the repo.

The CLI scaffolds a Next.js app or adds styled components to an existing project. Package-manager tabs use the runners and flags documented in the CLI README. Python commands come from the Python package docs.

npm 
npx assistant-ui@latest create
npx assistant-ui@latest init
npx assistant-ui@latest init --yes
npm install @assistant-ui/react @assistant-ui/ai-sdk ai

create starts a project. init adds assistant-ui to an existing project, and falls back to create when no package.json is found. Pass --yes when the shell cannot prompt, including CI. The npm install line is the direct package install from the README.

pnpm 
pnpm dlx assistant-ui@latest create --use-pnpm
pnpm dlx assistant-ui@latest init --yes --use-pnpm

The CLI README lists pnpm dlx assistant-ui@latest, and init accepts --use-pnpm and --yes.

yarn 
yarn dlx assistant-ui@latest create --use-yarn
yarn dlx assistant-ui@latest init --yes --use-yarn

The CLI README lists yarn dlx assistant-ui@latest, and init accepts --use-yarn.

bun 
bunx assistant-ui@latest create --use-bun
bunx assistant-ui@latest init --yes --use-bun

The CLI README lists bunx assistant-ui@latest, and init accepts --use-bun.

shadcn 
npx shadcn@latest add https://r.assistant-ui.com/thread.json

The installation guide also shows a components.json registry at https://r.assistant-ui.com/styles/{style}/{name}.json. Styles whose names start with base- receive Base UI components. Other styles receive Radix components. Existing Radix projects can keep https://r.assistant-ui.com/{name}.json.

pip / uv 
pip install assistant-stream[langgraph]
pip install assistant-ui-sync-server-api
uv add assistant-ui-sync-server-api

assistant-stream 0.0.36 requires Python >=3.10 and <4.0. The langgraph extra is documented in python/assistant-stream/README_LANGGRAPH.md. assistant-ui-sync-server-api 0.1.1 is the Python client for the sync server API and requires Python >=3.10. Its README shows both pip and uv.

pnpm 
pnpm install
pnpm turbo build
cd apps/docs
pnpm dev
pnpm changeset

From CONTRIBUTING. The root package.json sets packageManager pnpm@12.15.0 and engines node >=24.11. Some packages need the turbo build before dev. pnpm changeset is how published package edits get a changeset.

Usage · README 
"use client";

import { AssistantRuntimeProvider } from "@assistant-ui/react";
import { useChatRuntime } from "@assistant-ui/ai-sdk";
import { Thread } from "@/components/assistant-ui/elements/thread.aui";

export function Chat() {
  const runtime = useChatRuntime();
  return (
    <AssistantRuntimeProvider runtime={runtime}>
      <Thread />
    </AssistantRuntimeProvider>
  );
}

The first runtime is one hook.

useChatRuntime connects to the Vercel AI SDK out of the box. Swap it for useLangGraphRuntime, useDataStreamRuntime, or any custom runtime to integrate with your own backend. The snippet above is the Usage example from the README.

CLI templates

  • default — Default template with Vercel AI SDK. npx assistant-ui create
  • minimal — Bare-bones starting point. npx assistant-ui create -t minimal
  • cloud — Cloud-backed persistence starter. npx assistant-ui create -t cloud
  • cloud-clerk — Cloud-backed starter with Clerk auth. npx assistant-ui create -t cloud-clerk
  • cloud-harness — Hosted harness with a shared conversation. npx assistant-ui@latest cloud setup my-app
  • langchain — LangGraph starter with the react-langchain adapter. npx assistant-ui create -t langchain
  • mcp — MCP tools and MCP Apps renderer starter. npx assistant-ui create -t mcp
  • eve — Eve agent and Next.js starter. npx assistant-ui create -t eve
  • --native / --ink — Expo / React Native, or a React Ink terminal project. Also --example, such as with-ai-sdk-v7.

FAQ

License, shape, backends, CI.

The LICENSE file is the MIT License, copyright 2026 AgentbaseAI Inc. The README says the project is MIT, with optional Assistant Cloud for managed thread persistence and analytics. The library does not require Cloud.
You compose primitives and bring your own styles. The README sets that against a single monolithic chat component. Elements are the styled, installable layer. Primitives are the unstyled accessible layer, with Root, parts, asChild, and AuiIf. The CLI ships a starter in Base UI by default, or Radix UI.
useChatRuntime targets the Vercel AI SDK. The README says to swap in useLangGraphRuntime, useDataStreamRuntime, or a custom runtime. Named packages: @assistant-ui/ai-sdk, @assistant-ui/react-langgraph, @assistant-ui/react-langchain, @assistant-ui/react-ag-ui, @assistant-ui/react-a2a, @assistant-ui/react-google-adk, @assistant-ui/react-opencode, @assistant-ui/react-data-stream, and assistant-cloud. Models named in the README: OpenAI, Anthropic, Google Gemini, Mistral, Perplexity, AWS Bedrock, Azure, Fireworks, and Ollama, plus community providers via the AI SDK. The installation guide also lists Groq, Cohere, Google Vertex, and Chrome AI.
In a non-interactive shell, pass --yes: npx assistant-ui@latest init --yes. Without it, init exits because it cannot prompt. A pull request that changes a published package's shipped files needs a changeset (pnpm changeset); CONTRIBUTING says the Changeset Semver Check fails the PR otherwise. Every pull request gets a review tier from T0 to T3. Merge waits on the checks named there, including autofix, Build Changed Packages, Typecheck Changed Packages, Review Policy Scripts, Test Coverage, and review-tier, then the merge queue.
@assistant-ui/react 0.15.32 declares peer dependencies react and react-dom at ^18 or ^19. The deprecation policy says the project aims to keep the API stable. Anything marked unstable_ or experimental_, anything marked internal, and the RuntimeCore API may change in any release. Beta features, including styled UI components and shadcn/ui styles, get a notice shorter than one month. Stable features get a notice longer than three months.
