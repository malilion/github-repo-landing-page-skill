02 — Three rings

A thin host. pi stays the engine.

ThinkRail runs pi in-process and bridges it to this UI. pi owns models, skills, compaction, cost, and session state. ThinkRail owns the workspace, the editor, and the wire.

apps/cli and apps/desktop launch packages/server. packages/contracts is the wire. apps/web is the client.

Engine host

packages/server + packages/shared

A Bun.serve HTTP and WebSocket host with one in-process pi session per chat, launched by the CLI or the Electrobun desktop shell. App state lives under ~/.thinkrail. This repository's catalog pins @earendil-works/pi-coding-agent, pi-ai, pi-agent-core, and pi-tui at 1.4.0.

pi is the only engine

createAgentSession runs in-process. pi owns the model registry, system prompt, skills, extensions, compaction, cost, and session state.

Feed pi, then get out of the way

Features shape the agent through prompt context, files, pi's own skills and extensions, and the flags a session starts with. The host shows what pi reports.

Your tools, your credentials

git, gh, and model access go through your git, your gh, and pi's provider auth. ThinkRail keeps no accounts of its own. Who can reach a host is a network decision; the architecture names Tailscale ACLs.

03 — Capabilities

From a worktree to an open pull request

Every card is a capability described in the README or the product goal. This page leaves out anything those sources do not state.

Isolation

Isolated workspaces

Any git repository can be a project. A workspace ThinkRail creates is a git worktree with its own branch and directory, so agents work in parallel. You can attach an existing worktree, or explicitly work in the project folder itself — the Default workspace.

Isolation

Settled shelf and branch position

Finished and dormant workspaces settle onto a per-project shelf when their pull request merges or closes, or after a quiet week, and return when you work in them. The top bar shows where the active branch stands against origin and its pull request.

Workbench

An IDE around the agent

A splittable workbench of Monaco editor tabs, a Files tree with live git marks, a Changed view, terminals, and documents — scoped to the active workspace. You can also open the worktree in an IDE you already have installed.

Workbench

Anchored review

Leave review comments on files and diffs and send them to a chat as structured context. It is local review on the worktree, collected even before the agent starts.

Agent

Chats that stream with the engine

Several concurrent pi sessions per workspace, each with its own model and the token and cost readout pi reports. Steer a running turn, or queue a follow-up.

Agent

Plans, subagents, background commands

You and the agent share a plan you can edit. A completed step can be committed and reviewed on its own. Subagents run in isolated child sessions. Background commands run without holding the turn. Each chat's Resources view can watch and stop them.

Knowledge

Specs as ground truth

A connected graph of SPEC.md files lives beside the code. The agent reads, searches, and maintains it through spec_* tools, so intent survives the session. The read-only Specs tool renders that graph as a tree.

Knowledge

Skills and workflows

Portable Agent Skills you already keep for other coding agents are read in place. Bundled workflows guide project setup, design brainstorming, and shipping a pull request through your own gh.

Agent

Tools beyond the shell

Web research, structured multiple-choice questions asked in chat, and inline diagrams, comparisons, and file previews. A proposed UI change shows up as a before/after you can comment on. The same two tools publish for vanilla pi: @thinkrail/pi-ask-user-question 0.1.0 and @thinkrail/pi-visualize 0.2.0.

Trust

MCP, with a confirm on the call

ThinkRail reads the MCP servers in your pi mcp.json, and you can add servers and a few presets from Settings. Calls a server does not mark read-only ask in the chat first. Tools you trust can be always allowed per project. Servers a repository defines stay off until you approve them. OAuth sign-in lives in Settings.

Trust

Your providers, your pi setup

Sign in with JetBrains AI, or connect any provider through pi's own auth. ThinkRail reads ~/.pi/agent. Another config directory, or extra environment variables for the agent, terminals, and MCP servers, is Settings → Environment, applied on the next start. A variable you set at launch still wins.

Trust

Analytics with a narrow payload

Basic usage events tie to a random installation ID and leave out prompts, code, files, credentials, and account identity. Error reports are always sent as a classifier — type, code, and ThinkRail stack frames — and leave out message text. Additional sharing lives in Settings → Privacy. thinkrail --no-analytics turns that extra sharing off for the run.

Ship

Publish, push, open the PR

The top bar's next step is publish, push, or open a PR described from the plan, the commits, your PR template, or an agent-written draft — through your gh. An open GitHub PR shows CI checks and the review decision: mark ready, hand failing checks or a diverged branch to the agent, merge with the repository's last-used method, reopen, or delete the remote branch.

Workbench

Language and themes

Settings → Language follows the system or a language you pick. English, Japanese, Simplified Chinese, and Spanish ship built-in. A translated en.json in ~/.thinkrail/locales applies as you save. Appearance ships dark, light, minimal, and high-contrast themes; a copied *.theme.json in ~/.thinkrail/themes applies the same way. Agent replies stay as the agent wrote them.

04 — Install

Desktop installer, or one command

Two forms ship together: a native desktop installer and the self-contained thinkrail CLI, both with SHA256SUMS on the releases page. You need git on PATH and a model provider — JetBrains AI in the app, or pi's own auth. The first launch connects a provider and picks a project. Start a new project creates an empty git repository under ~/thinkrail. Add project → Clone repository… clones a Git URL into a new folder on the computer running ThinkRail and leaves existing destination folders alone. Package manifests in this checkout read 0.0.0; published version numbers live on the releases page.

thinkrail 
curl -fsSL https://raw.githubusercontent.com/JetBrains/thinkrail/main/install.sh | bash

thinkrail ~/code/my-repo

The installer downloads the matching binary, checks its SHA-256, and puts thinkrail on your PATH. thinkrail --help lists flags. thinkrail --version prints the build. The same curl command works from Git Bash on Windows.

The same command works from cmd and PowerShell. Channel, version, prefix, and PATH options are environment variables: THINKRAIL_CHANNEL, THINKRAIL_VERSION, THINKRAIL_PREFIX, THINKRAIL_NO_MODIFY_PATH.

Download the thinkrail-desktop-* asset from releases. macOS 14+ opens the DMG for Apple Silicon or Intel. Windows x64 extracts the setup ZIP and runs its setup executable in place, next to its payload. Linux extracts the setup tarball and runs installer. The command above is the Linux desktop library line for Ubuntu 24.04 or newer: glibc 2.38+, GTK 3, WebKitGTK 4.1, Ayatana AppIndicator 3, and librsvg 2. Packaged stable and nightly builds offer updates in Settings → Updates and apply them only after Install & Restart.

--channel is stable or nightly. A pinned --version has to belong to the selected channel. On Windows the same switches are THINKRAIL_CHANNEL and THINKRAIL_VERSION. Installed stable and nightly CLI hosts offer Run Update in Settings → Updates, which runs thinkrail update on the host machine. thinkrail uninstall removes the executable and the PATH entry the installer added. ~/.thinkrail is kept unless you ask to delete it.

bun run dev boots the host and the web client together; Ctrl+C stops both. Browser launcher: bun run --filter @thinkrail/cli dev. Desktop shell: bun run desktop:dev. Development needs Bun 1.4.4, Node.js ≥ 22.19, and an authenticated pi provider. A source checkout exposes no application updater — update it with git and rebuild.

Platform notes from the README

macOS 14+

DMG for Apple Silicon or Intel. The CLI is a signed binary and is not yet notarized. Signed and notarized desktop DMGs go through the JetBrains release pipeline; older published DMGs and local builds may still be unsigned, and Gatekeeper can block them.

Windows x64

JetBrains signs the CLI, the desktop setup executable, and every executable and DLL the desktop app installs.

Linux x64 / ARM64

The setup tarball and the CLI are unsigned. Desktop builds need glibc 2.38+ with GTK 3, WebKitGTK 4.1, Ayatana AppIndicator 3, and librsvg 2 — Ubuntu 24.04 or newer.

05 — FAQ

Licensing, pi, privacy, CI

Apache License 2.0. Copyright 2026 JetBrains s.r.o. Contributions are licensed the same way and follow the Code of Conduct. The license text is in LICENSE.

ThinkRail is a thin host around pi. pi keeps models, skills, compaction, cost, and session state, and ThinkRail reads your ~/.pi/agent config. The workbench adds worktree isolation, Monaco, files, terminals, diffs, anchored review, and the spec graph. Two tools also ship as plain pi packages: @thinkrail/pi-ask-user-question 0.1.0 and @thinkrail/pi-visualize 0.2.0. Settings → Extensions lists ThinkRail extensions and can switch each one off.

ThinkRail has no accounts of its own. Usage analytics carry a random installation ID and leave out prompts, code, files, credentials, and account identity. Error reports are always sent with the error type and code and ThinkRail stack frames, and they leave out message text, paths, names, and URLs. Additional product usage is shared only while Settings → Privacy is on. thinkrail --no-analytics or THINKRAIL_NO_ANALYTICS=1 turns that extra sharing off for the run. With additional sharing on, a packaged build may open the ThinkRail blog once to link the installation to the site visit that brought you here — only where you accepted marketing cookies or no consent is required — and that link expires after 30 days. Analytics go through PostHog. The website's PostHog surveys can ask for an email after a desktop download if you choose to enter one.

The CLI and desktop app need git on PATH and a model provider: JetBrains AI from the app, or pi's provider auth. Desktop targets are macOS 14+ (Apple Silicon or Intel), Windows x64, and Linux x64 / ARM64. Building from this repository needs Bun 1.4.4 and Node.js ≥ 22.19. The catalog pins @earendil-works/pi-coding-agent at 1.4.0.

Packaged stable and nightly desktop builds check in the background and offer Download → Preparing update → Install & Restart in Settings → Updates. Nothing is applied until you choose Install & Restart. The updater appears when the package carries a valid HTTPS feed identity. Installed CLI hosts offer Run Update, which runs thinkrail update on the host machine and then asks you to restart the host. You can also run thinkrail update yourself.

When a GitHub pull request is open, the top bar shows its CI checks and review decision. You can hand failing checks or a diverged branch to the agent, and merge with the repository's last-used method through your gh. People contributing to ThinkRail run bun run lint, bun run typecheck, bun run test, and the no-agent bun run e2e gate. The commands are in CONTRIBUTING.md.

The app ships English, Japanese, Simplified Chinese, and Spanish (en, ja, zh-CN, es in packages/locales). Drop a translated en.json into ~/.thinkrail/locales and it applies as you save. Agent replies and tool output stay as written. Traditional Chinese on this page is the page's own switch, separate from the app catalog.

pi install npm:@thinkrail/pi-ask-user-question adds structured questions. pi install npm:@thinkrail/pi-visualize adds diagrams and previews. Versions in this repository: 0.1.0 and 0.2.0. Inside ThinkRail, Settings → Extensions can switch each ThinkRail extension off.
