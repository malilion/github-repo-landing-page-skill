A2UI v0.9 · SDK 1.7.0 · released 2026-10-19

Generative UI, rendered natively across iOS, Android, and HarmonyOS.

AGenUI fully implements Google's open-source A2UI v0.9 protocol. A shared C++ core parses the stream and keeps a virtual component tree. Three native renderers then draw interactive cards, forms, lists, images, and media with system UI.

The project is under active development. Contributions, feedback, and discussion are welcome.

What's new in v1.7.0

Released 2026-10-19 · CHANGELOG.md

  • resolveCalls

    Recursively executes FunctionCalls nested in JSON and replaces each call node with its return value.

  • registerDeepParseProperty

    Enables nested binding resolution inside function arguments and event context for action.

  • label

    ChoicePicker and Slider now render and measure label, including wrap, dynamic updates, and clearing.

Also in 1.7.0: Android keeps line-height after dynamic text updates. HarmonyOS fixes Image taps that carry an action, checks RichText and Tabs event types, and corrects ChoicePicker teardown order. Playground catalog URL references are updated.

Capabilities

What the SDK actually ships.

Taken from the README, CHANGELOG, catalog, and package manifests. Counts below are the ones those files state.

Real-time streaming render

Structured component descriptions arrive incrementally from the LLM and update on screen. The Quick Start drives a session with beginTextStream, receiveTextChunk, and endTextStream.

Native drawing on three OSes

iOS, Android, and HarmonyOS use system UI. The README states that core scenes such as page scrolling hold a 120 fps refresh rate.

Shared C++ core

The C++ layer parses the stream, manages the virtual component tree, caches draw data, resolves theme and style, and diffs component changes before the platform renderers paint.

Design tokens, light and dark

registerDefaultTheme takes theme JSON and design-token JSON. setDayNightMode accepts "light" or "dark", and surfaces that are already up refresh their colors.

22 built-in components

18 components implement the A2UI protocol on all three platforms. Four more ship with the SDK and are outside the spec: Table, Carousel, Web, and RichText.

Custom component API

Register extra native components at runtime. The model can then emit them by name. Playground registers Chart, Markdown, and Lottie to show the same API.

Freestanding catalog

agenui_catalog.json inlines every external $ref. The README says it covers 25 components and 14 functions (validation, formatting, logic, and URL navigation), plus Styles and TextStyles. Supply it as a catalogId in supportedCatalogIds.

On-device function calls

Register client tools the model can invoke. v1.7.0 adds resolveCalls for nested FunctionCalls, and registerDeepParseProperty for multi-level bindings inside action arguments and event context.

A2UI generation skill

skills/a2ui-generation mounts into Agent Skills runtimes. The README names Claude Code, Cursor, Codex, Gemini CLI, Windsurf, and GitHub Copilot, and states 55+ runtimes. Default shape is one Card. An explicit layout or style request wins over that default.

Studio, local and BYOK

AGenUI Studio turns a description into protocol, previews it, validates with the skill's validate_a2ui.py, and pushes to Playground by QR code. npm package agenui-studio is 0.1.5. Documented providers: DeepSeek, Qwen, GLM, Moonshot, MiniMax, OpenAI, Gemini, Anthropic, OpenRouter. Keys stay under ~/.agenui.

Go agent SDK

agent_sdks/go streams partial UI, validates topology, reachability, circular references, and recursion depth, and can build an LLM system prompt from a catalog. A sample lives at samples/go/rizzcharts.

Component vocabulary

Names and descriptions follow the README tables. Protocol components are on all three platforms. SDK extensions are bundled but are not part of the A2UI spec. Playground components show the custom-component API.

FAQ

License, scope, and CI.

AGenUI is released under the Apache License, Version 2.0. The LICENSE file is in the repository root. NOTICE says the project's own source, outside the third-party pieces it lists, is Apache-2.0. It also says the vendored iksemel library is LGPL-2.1, built as a shared library on HarmonyOS, and not used on Android or iOS. NOTICE describes the engine source as not a derivative of that library.

Google's A2UI v0.9 is the protocol. AGenUI is an implementation of that protocol: a shared C++ core, native renderers for iOS, Android, and HarmonyOS, the freestanding catalog, the generation skill, Studio, and the Go agent SDK. The README describes drawing interactive cards, forms, lists, images, and media players with system UI. This repository does not publish a scorecard against other named UI SDKs, so this page does not invent one.

The skill is a directory you mount in an agent runtime with npx skills add AGenUI/AGenUI. Studio is a local browser workbench, npx agenui-studio, that reuses the skill's design rules and scripts/validate_a2ui.py, then sends a QR code to AGenUI Playground on a device. Studio's README says API keys, config, and generated protocols stay on the machine under ~/.agenui.

.github/workflows has live pipelines: CI - Android runs ./scripts/android/build.sh (the workflow sets up JDK 17), CI - iOS runs ./scripts/ios/build.sh on macos-26 after selecting Xcode 26.2, and CI - HarmonyOS runs ./scripts/harmony/build.sh. They trigger on push and pull request to main, with path filters. Release workflows run for tags that start with AGenUI-; Studio Release packs agenui-studio.zip on those tags. The C++ gtest file tests/cpp/ci/github-actions.yml says it is not a live workflow until copied to .github/workflows/. Host tests: ./tests/cpp/ci/run_tests.sh. Device integration: ./tests/integration/run.sh, with --android, --ios, or --harmony.

core/include/agenui_version.h sets AGENUI_VERSION to 1.7.0. CHANGELOG dates that release 2026-10-19. The published iOS podspec is 1.7.0 with deployment target 13.0. QuickStart lists Android API 21 or later, and HarmonyOS NEXT API 17 or later. The separate npm package agenui-studio is 0.1.5. The QuickStart local Maven snippet still shows implementation 'com.amap.genui:agenui-sdk:0.1.0'.

Fork, branch from main (fix/… or feat/…), test on the platforms you change, and open a pull request to main. At least one maintainer approval is required. C++, Swift, and Java follow the Google Style Guide. ArkTS follows OpenHarmony. Larger changes start with an issue. See CONTRIBUTING.md. Issues and Discussions are on GitHub. The README lists the email tengjixiang.ttjx@alibaba-inc.com, plus DingTalk and WeChat groups.
