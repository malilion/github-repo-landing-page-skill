設計工程師

給設計工程師的 介面元件庫

給同時做設計與實作的人。把 React 動效元件，透過 shadcn registry 加進已使用 Tailwind 的專案。原始碼在這個倉庫，授權為 MIT。

開啟安裝說明

MIT 授權 · 套件版本 0.1.0 · registry.json 有 75 個 registry:ui 項目

結果

裝得進專案、也改得了的動效

Magic UI 是這個倉庫裡給設計工程師的介面元件庫。元件給已使用 Tailwind CSS 的 React 與 Next.js 專案，並透過 shadcn registry 加入。

登錄檔裡已有名字的動效

Marquee 的說明是無限捲動，用來顯示文字、圖片或影片。Blur Fade 用來淡入淡出內容。Border Beam 讓一道光沿容器邊緣移動。Shimmer Button 讓光沿著按鈕周圍走。以上都是 registry.json 的描述。

一條指令把原始碼加進專案

先初始化 shadcn，再用 add 指令指定 @magicui 的 slug。registry.json 把檔案 target 設在 components/magicui。skill 示範的 import 來自 @/components/ui，並說明 alias 不同時要自行調整。

文件涵蓋安裝、元件與 MCP

README 指向 magicui.design/docs。skill 另外列出元件文件、安裝頁，以及給 AI IDE 工作流程的 MCP 設定頁。

貢獻步驟寫在指南裡

貢獻指南寫新增元件或效果要寫 5 個檔案，再提交 pnpm build:registry 產生的產物，並說大約 10 分鐘。README 則說加上你自己的元件大約 5 分鐘。

使用方式

三個步驟加入元件

  1. 01

    初始化 shadcn

    skill 要求專案是使用 Tailwind CSS 的 React 或 Next.js。在該專案執行一次 init。

  2. 02

    加上元件 slug

    用 registry 的 add 指令加上 @magicui 與 slug。skill 的範例指令使用 magic-card。Globe 在 registry.json 列出依賴 cobe 與 motion。Marquee 的 keyframes 也在同一份檔案。

  3. 03

    接上區塊並做檢查

    保留元件 API，優先用 props 與 className，不要先改產生出來的內部實作。結束前檢查鍵盤操作、窄螢幕是否溢出，以及同一個視窗是否疊了太多高強度動效。

下面的指令摘自倉庫 skill 與 CONTRIBUTING.md。

給使用元件的人。來自 Magic UI skill。

npx shadcn@latest init
npx shadcn@latest add @magicui/magic-card

給貢獻者。步驟來自 CONTRIBUTING.md。請把網址裡的 YOUR_USERNAME 換成你的 GitHub 使用者名稱。這份檢出的 .nvmrc 是 22。package.json 要求 Node 大於等於 22.14.0、pnpm 大於等於 9，packageManager 為 pnpm@9.15.0。

git clone https://github.com/<YOUR_USERNAME>/magicui.git
cd magicui
pnpm i
touch .env.local && echo "NEXT_PUBLIC_APP_URL=http://localhost:3000" > .env.local
pnpm dev

開 pull request 之前，貢獻指南列出的本機檢查。package.json 把 check 定義為 lint、typecheck、format:check 與 registry-deps:check。

pnpm check
pnpm build:registry
pnpm build

問題

安裝之前

Magic UI 是什麼？

README 稱 Magic UI 為給設計工程師的介面元件庫（UI library for design engineers）。registry.json 的 homepage 是 https://magicui.design。倉庫內的 skill 說明這些元件用在已採用 Tailwind CSS 的 React 或 Next.js 專案。

如何加入一個元件？

skill 寫的是先執行一次 npx shadcn@latest init，再執行 npx shadcn@latest add @magicui/ 加上元件 slug。範例是 @magicui/magic-card。skill 的 import 路徑寫 @/components/ui，registry.json 的檔案 target 則是 components/magicui。若專案的 alias 不同，請改 import。

授權是什麼？

LICENSE.md 是 MIT 授權，著作權人寫 Magic UI。README 連到該檔。散佈複本時必須保留著作權聲明與許可聲明。

如何在本機跑這個倉庫？

貢獻指南寫：fork、clone 你的 fork、執行 pnpm i、建立 .env.local 並寫入 NEXT_PUBLIC_APP_URL=http://localhost:3000，然後執行 pnpm dev。這份檢出的 .nvmrc 內容是 22。package.json 的 engines 要求 Node 大於等於 22.14.0、pnpm 大於等於 9，packageManager 是 pnpm@9.15.0。

專案腳本會檢查什麼？

package.json 把 check 定義為 lint、typecheck、format:check 與 registry-deps:check。貢獻指南另外要求：改了 registry 或 config/site.ts 要執行 pnpm build:registry，以及執行 pnpm build，因為 CI 也會跑建置。提交訊息走 Conventional Commits，由 commitlint 檢查。git hooks 由 lefthook 安裝。

文件在哪裡？

README 寫前往 https://magicui.design/docs。skill 另外列出 https://magicui.design/docs/components、https://magicui.design/docs/installation 與 https://magicui.design/docs/mcp。

可以在哪裡提問？

README 的 Discord 是 http://magicui.design/discord，邀請連結是 https://discord.com/invite/87p2vpsat5，Twitter 是 https://twitter.com/magicuidesign。貢獻指南說需要協助就開 GitHub issue，並指向範例 pull request：https://github.com/magicuidesign/magicui/pull/780。

版本 0.1.0 是不是可以直接用套件名稱安裝？

根目錄 package.json 的 name 是 magicui、version 是 0.1.0、private 是 true。這頁不把該版本寫成以套件名稱安裝的指令。skill 記載的使用者安裝方式是 shadcn registry 的 add 指令。

元件無法 import 或沒有畫面時呢？

skill 寫：若 components.json 或 registry 初始化失敗，先執行 shadcn init；alias 不符就改 import；文件若要求全域 CSS keyframes 就補上；並安裝該元件列出的依賴。例如 Globe 在 registry.json 列出 cobe 與 motion。Marquee 的 keyframes 寫在 registry.json。
